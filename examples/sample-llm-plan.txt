About this example
------------------
This file is the plan.txt the shipped wizard (cmd/nvcheckup/llmplan.go, internal/llmplan, NVCheckup
v0.2.3 development build of this commit) wrote for the first worked example of
docs/roadmap/spark-support.md section 7.5: Llama 3.1 8B Instruct in its default BF16 weights, --profile
agent (1 + 3 subagent streams x 32768 tokens), f16 KV cache, vLLM. It was produced offline with --report
from a report.json serialised from the healthy GB10 fixture (internal/analyzer/fixtures, the same
strings as the simulated CI scenario .github/fieldtest/scenarios/gb10.json: MemTotal 125513944 kB =
119.7 GiB, driver 580.159.03, CUDA 13.0, OTA2607 torn 0, Docker with NVIDIA Container Toolkit 1.19.0).
The fixture probes no python, so the torch and Triton rows are SKIP rather than WARN and the exit code
is 0; the simulated gb10 CI job runs the same command against its report.json and asserts
fit.total_gib 51.0 and fit.gpu_memory_utilization 0.40 from plan.json. Regenerate with:

  go build ./cmd/nvcheckup && ./nvcheckup llm-plan --report report.json --model llama-3.1-8b-instruct \
      --profile agent --runtime vllm --json --out plan && cp plan/plan.txt examples/sample-llm-plan.txt

No plan has been produced on real GB10 or N1X hardware yet (issue #3); every figure above is the
spec's formula, not a measurement of a machine.
