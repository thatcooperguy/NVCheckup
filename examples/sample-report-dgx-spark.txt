About this example
------------------
This report is the text renderer's output for the simulated GB10 fixture
(internal/analyzer/fixtures.GB10, spec docs/roadmap/spark-support.md section 10)
run through the analyzer in full mode. It is byte-identical to the golden file
internal/report/testdata/gb10_report.txt, which `go test ./internal/report -run
Golden -update` regenerates; nothing in it is hand-written. The fixture mirrors
the healthy DGX Spark scenario that drives the "Linux field test (simulated GPU)"
CI job (.github/fieldtest/scenarios/gb10.json): MemTotal 125513944 kB, nvidia-smi
memory [N/A], compute capability 12.1, the misreported GEN 1@1x link on the
on-package GPU, DGX OS image 7.2.3 (DGX_SWBUILD_VERSION) with OTA 7.5.0
(DGX_OTA_VERSION, OTA2607) and driver 580.159.03, and two ConnectX-7 twins of one
cabled cage. Values the spec leaves open (dates, addresses, hostnames, the
DGX_SWBUILD_* / commit / FastOS placeholders inherited from the draft scenario)
are synthetic test data, and the fixture is healthy, so no WARN or Advisory step
appears; see internal/report/testdata/rtx_spark_report.txt for one. Nothing here
has been verified on hardware yet: a real capture is tracked in
https://github.com/thatcooperguy/NVCheckup/issues/3 and scripts/spark-capture.sh
produces one.
