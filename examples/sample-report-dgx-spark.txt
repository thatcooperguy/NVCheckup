About this example
------------------
This report is a SIMULATED capture, not a recording from hardware. It was produced by the shipped
text renderer (internal/report/text.go) and analyzer from the GB10 fixture that pins the renderer's
golden files (internal/analyzer/fixtures, internal/report/testdata/gb10_report.txt): the same
machine that the "Linux field test (simulated GPU)" CI job replays through shims and NVC_SIM_ROOT
from .github/fieldtest/scenarios/gb10.json (spec section 10). Two deliberate deviations from the
healthy fixture were added so that the report shows WARN findings and an Advisory step: the two
port-0 ConnectX-7 twins are cabled but unaddressed (cx7-up-no-ip, one finding per twin), and a
CUDA 12.8 PyTorch wheel is installed (arm64-cuda12-wheel-on-cuda13, which also produces the benign
capability-12.1 INFO). The version string is the fixture's; a real run prints the release it was
built from.

Sourced from public field reports cited in docs/roadmap/spark-support.md: MemTotal 125513944 kB
(119.7 GiB), the 0000000F:01:00.0 bus id, the [N/A] memory / fan / power-limit fields and the
GEN 1@ 1x misreport, driver 580.159.03 / CUDA 13.0 / compute capability 12.1, DGX OS 7.5.0 and
OTA2607, the dotted EC 3.5.8 / SoC 2.155.11 / PD 0.5.22 firmware versions (S4) and the driver,
firmware and kernel-module package names.

Placeholders pending a real capture: the fwupdmgr device names and the hex encodings shown in the
FIRMWARE block (0x03000508 and 0x00000516 are an arithmetic assumption that spark-rules.json marks
unconfirmed against fwupdmgr output), the dgx-dashboard, nvidia-spark-ota-check and

thermal-zone temperature, the ConnectX-7 rate string, the systemd unit states, the DKMS line, the
